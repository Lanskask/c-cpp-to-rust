## 0. Scope and posture

- Two Parts (`parts.tsv`): `cJSON` (`cJSON.c` + `cJSON.h` → `rust/src/cJSON.rs`) and `cJSON_Utils`
  (`cJSON_Utils.c` → `rust/src/cJSON_Utils.rs`), which depends on `cJSON`. Tests, `test.c`, `fuzzing/` and
  `library_config/` are not Parts.
- Stage 1 (Faithful port): same structure, same names, C ABI (`#[no_mangle] pub unsafe extern "C"`, `#[repr(C)]`) for
  every public symbol of `cJSON.h` and `cJSON_Utils.h`, `unsafe` allowed. You are translating, not improving.
- `struct cJSON` is `#[repr(C)]` with the C field order `next, prev, child, type_0, valuestring, valueint,
  valuedouble, string`: upstream tests read and write the fields directly (`misc_tests.c:398-401`).
- Stage 2 (Idiomatic pass): the API in §6, zero `unsafe`, acceptance rules in §10. Same behaviour, not same API.
- Engine for Stage 1: c2rust, per-feature runs, LLM polish (user decision 2026-10-10: the most deterministic
  route). One c2rust run per feature set in §3 (`""`, `locales`), merged by hand, then an LLM polish of each Part
  against this rulebook. c2rust has not been run on this Source yet, and it is untested on a multi-file Source with
  libc `sprintf`/`sscanf`/`strtod` calls (`PLAN.md`) (unverified). The gate alone decides acceptance.
- Run `cargo check` in the inner loop; `gate.py` alone decides acceptance.

## 4. Escape hatch and markers

As in the template §4. Stage 1: `unsafe` for pointer dereference, `static mut` access and libc calls; each `unsafe`
block that is not a direct pointer translation carries `// SAFETY: <why>`. Stage 1 accesses fields through the raw
pointer (`(*item).next`) and does not keep a `&mut` created from a raw pointer alive while the same pointer is passed
to another function (aliasing UB). Stage 2: none, anywhere under `rust/src/`.

Markers: `TODO(port):`, `PERF(port):`, `BUG(port):`, `QUIRK(port): Q<n>`, `DEVIATION(port): D<n>`, exact spelling, one
comment line directly above the site. Exact marker sites are fixed after the stress test (as jsmn RP11); until then a
marker goes on every C site cited in §8 and §9.

- **UNKNOWN rule:** when neither this rulebook nor the idiom table decides a case, take the most conservative mapping,
  mark `TODO(port):`, and keep going.
- **BUG rule:** defective original behaviour is reproduced, not fixed (Q15, Q20 carry `BUG(port):` as well as
  `QUIRK(port):`). Fixes are separate, flagged changes after the Pilot passes.

## 5. Naming and paths

- Part → target file: `cJSON` → `rust/src/cJSON.rs`, `cJSON_Utils` → `rust/src/cJSON_Utils.rs` (`parts.tsv`);
  `rust/src/lib.rs` only declares the two modules and the crate attributes.
- Names: Stage 1 keeps C names (`#![allow(non_camel_case_types, non_snake_case, non_upper_case_globals)]`); the
  `type` field is `type_0` (c2rust spelling). Stage 2 uses Rust naming (§6).
- Shared types (`cJSON`, `cJSON_bool`, `cJSON_Hooks`, the `cJSON_*` type constants) live in `rust/src/cJSON.rs`;
  `cJSON_Utils.rs` imports them from `crate::cJSON` and calls only the public C-ABI functions of `cJSON`, as the C file
  does. Its private helpers with the same C names as helpers in `cJSON.c` (`compare_double`, `get_array_item`,
  `get_object_item`, `cJSONUtils_strdup`) stay private copies in Stage 1.
- Translated tests: `rust/tests/<upstream test file stem>.rs`; Stage 2 driver: `rust/examples/dump.rs`; both reach the
  crate only through the Judge adapter `rust/tests/adapter/mod.rs` (see `judge.md`).

## 7. Error model

- cJSON signals failure by `NULL` / `false` (E2); the parse error position is the global `cJSON_GetErrorPtr()`
  (G3, D9). `cJSON_Utils` patch functions return status codes `0..13` (`cJSON_Utils.c:807-1036`, Q24): Stage 2 keeps
  them as `enum PatchError` with `fn code(self) -> i32` returning the exact C value (E1).
- **allocation-guards**: every `NULL` check after `hooks->allocate`/`reallocate` (e.g. `cJSON.c:199-203`, `243-247`,
  `357-361`, `540-564`, `863-866`, `1166-1170`, `1252-1255`). Stage 1 keeps them; Stage 2: D1.
- **precondition-guards** (kept, same result in both Stages): `NULL` arguments, negative indices and lengths
  (`cJSON.c:1321-1324`, `1352-1355`, `1943-1946`), corrupted list (`cJSON.c:2260`, `2349-2352`), nesting and circular
  limits, `ensure` size limits (`cJSON.c:500-510`), `noalloc` buffer too small (`cJSON.c:518-520`).
- Partial state after an error (E4): a failed parse frees the partial tree and sets the error position (Q12);
  `cJSON_PrintPreallocated` leaves the bytes written so far in the caller's buffer (Q6); `cJSONUtils_ApplyPatches`
  keeps the patches applied before the failing one (no rollback, `cJSON_Utils.c:1054-1062`).

## 10. Judge and acceptance

- Gate: `make pilot-cjson STAGE=<n>` over the feature sets `""` and `locales` (§3), both run in the C locale.
- Upstream tests the Judge links (`tests/CMakeLists.txt`): 18 `cJSON` tests `parse_examples`, `parse_number`,
  `parse_hex4`, `parse_string`, `parse_array`, `parse_object`, `parse_value`, `print_string`, `print_number`,
  `print_array`, `print_object`, `print_value`, `misc_tests`, `parse_with_opts`, `compare_tests`, `cjson_add`,
  `readme_examples`, `minify_tests`, plus 3 `cJSON_Utils` tests `json_patch_tests`, `old_utils_tests`,
  `misc_utils_tests` (data in `tests/inputs/` and `tests/json-patch-tests/`). Unity from `tests/unity`.
- Linking problem: every test includes `tests/common.h`, which does `#include "../cJSON.c"`, so the tests compile the
  C library into themselves. The Judge replaces `common.h` with a shim that includes `cJSON.h`. With that shim, 8
  tests use only the public API (`cjson_add`, `compare_tests`, `json_patch_tests`, `minify_tests`,
  `misc_utils_tests`, `old_utils_tests`, `parse_with_opts`, `parse_examples`) and `readme_examples` needs only a copy
  of `compare_double`. The other 12 use static internals (`parse_*`, `print_*`, `ensure`, `skip_utf8_bom`,
  `global_hooks`, `parse_buffer`, `printbuffer`; `misc_tests` and the `parse_*`/`print_*` files).
  Decision (user, 2026-10-10): Stage 1 exports those internals as `pub` under the cargo feature `test-internals`, with
  `#[repr(C)]` `parse_buffer`/`printbuffer` (c2rust keeps static functions private, so without this the tests
  cannot link). The Differential harness also covers their inputs.
- Stage 1: `cargo check`, `cargo test`, the upstream tests above linked to the staticlib (C only), Differential
  harness (`harness/run.py`: C driver parse → print formatted/unformatted, minify, error position vs original).
- Stage 2: translated tests `rust/tests/<stem>.rs` (except the ones D1, D7, D11, D14 exclude, each listed in
  RUN-NOTES), Differential harness with `rust/examples/dump.rs`, clippy `-D warnings`, rustfmt, zero `unsafe`, no
  `unwrap()`/`expect()` on input-driven paths (others need an invariant comment) (decision 10).
