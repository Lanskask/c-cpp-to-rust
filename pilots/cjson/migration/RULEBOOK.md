## 0. Scope and posture

- Two Parts (`parts.tsv`): `cJSON` (`cJSON.c` + `cJSON.h` → `rust/src/cJSON.rs`) and `cJSON_Utils`
  (`cJSON_Utils.c` → `rust/src/cJSON_Utils.rs`), which depends on `cJSON`. Tests, `test.c`, `fuzzing/` and
  `library_config/` are not Parts.
- Stage 1 (Faithful port): same structure, same names, C ABI (`#[no_mangle] pub unsafe extern "C"`, `#[repr(C)]`) for
  every public symbol of `cJSON.h` and `cJSON_Utils.h`, `unsafe` allowed. You are translating, not improving.
- `struct cJSON` is `#[repr(C)]` with the C field order `next, prev, child, type_0, valuestring, valueint,
  valuedouble, string`: upstream tests read and write the fields directly (`misc_tests.c:398-401`).
- Stage 2 (Idiomatic pass): the API in §6, zero `unsafe`, acceptance rules in §10. Same behaviour, not same API.
- Engine for Stage 1: c2rust, per-feature runs, LLM polish (user decision 2026-10-10: the most deterministic
  route). One c2rust run per feature set in §3 (`""`, `locales`), merged by hand, then an LLM polish of each Part
  against this rulebook. c2rust has not been run on this Source yet, and it is untested on a multi-file Source with
  libc `sprintf`/`sscanf`/`strtod` calls (`PLAN.md`) (unverified). The gate alone decides acceptance.
- Run `cargo check` in the inner loop; `gate.py` alone decides acceptance.

## 4. Escape hatch and markers

As in the template §4. Stage 1: `unsafe` for pointer dereference, `static mut` access and libc calls; each `unsafe`
block that is not a direct pointer translation carries `// SAFETY: <why>`. Stage 1 accesses fields through the raw
pointer (`(*item).next`) and does not keep a `&mut` created from a raw pointer alive while the same pointer is passed
to another function (aliasing UB). Stage 2: none, anywhere under `rust/src/`.

Markers: `TODO(port):`, `PERF(port):`, `BUG(port):`, `QUIRK(port): Q<n>`, `DEVIATION(port): D<n>`, exact spelling, one
comment line directly above the site. Exact marker sites are fixed after the stress test (as jsmn RP11); until then a
marker goes on every C site cited in §8 and §9. A marker on a private helper that exists only to carry the deviation
or quirk (it is the C site's code: `malloc_unchecked` D2, `different` D20, `saturate` Q5) covers its call sites; a
marker on a public function does not cover its callers.

- **UNKNOWN rule:** when neither this rulebook nor the idiom table decides a case, take the most conservative mapping,
  mark `TODO(port):`, and keep going.
- **BUG rule:** defective original behaviour is reproduced, not fixed (Q15, Q20 carry `BUG(port):` as well as
  `QUIRK(port):`). Fixes are separate, flagged changes after the Pilot passes.

## 6. Stage 2 public API

Decided 2026-10-10 from the user's decisions (D1 and D11 revised, D21 added) and the review
`experiments/stage2_proposals_review.md`. User priority: the Rust rewrite stays as close to the C original's
functionality as possible; every divergence is a row of §8. Names of types and functions are free (Rust naming,
§5); the observables below are binding. Zero `unsafe` (§4).

### 6.0 Observability contract (amendment P1, 2026-10-10)

The §6 API lets the Judge adapter (`rust/tests/adapter/mod.rs`, whose header states the same contract) report every
value below in safe Rust, with no behaviour of its own beyond handle bookkeeping:

1. Identity: a `Copy + Eq + Hash` handle per node, stable while the node lives, across detach, add, replace and a
   root `remove` patch; equal iff same node (tests; `cJSONUtils_FindPointerFromObjectTo`, `cJSON_Utils.c:208`).
2. Fields of every node of every kind: the type word (kind bits with `Invalid` = 0, plus `IsReference` 256 and
   `StringIsConst` 512, D12); `valueint` and `valuedouble` as stored fields (Q5), each writable on its own (Q3);
   `valuestring` (also for `Raw`) and the key, each `Option<&[u8]>`.
3. Links `child`, `next`, `prev` with the C invariant: the first child's `prev` is the last child, the last child's
   `next` is none, a node in no list has `prev` none (`cJSON.c:2027-2058`, `2256-2292`); a Utils sort leaves the
   first child's `prev` stale (Q18).
4. Parse: end offset on success; on failure the error offset (Q12), also returned as the parse end
   (`cJSON.c:1209-1212`). A thread-local last-error offset follows the C reset rules of Q26 (D9).
5. Patch status codes 0-11 and 13, and 1 for a non-array patch list (Q23), through `PatchError::code()` (§7).
6. String arguments are `&[u8]` read up to the first NUL (C `strlen`); a stored value is the bytes before its first
   NUL (Q10; a caller can shorten it through a view, D21). A string reference keeps the caller's `&'static [u8]`
   without a copy; a longer `set_valuestring` value goes into a new buffer, a shorter one is copied in place
   (`cJSON.c:455-473`); the buffer address is observable (`misc_tests.c:581`, `711`, `718`).
7. The header macros as functions with the macro semantics (M2): `set_int_value` (`cJSON.h:281`, both fields, no
   saturation), `set_number_value`, `set_bool_value` (new type word or 0), children iteration.
8. The allocation hooks of §6.2 (D1): `allocate(size) -> bool` / `deallocate(size)` events at every C allocation
   and free site, with C sizes; dropping a returned buffer is a free event.
9. The writable views of §6.4 (D21).
10. An `Invalid` node is publicly constructible: a `remove` patch at path `""` overwrites the root with type 0
    (`cJSON_Utils.c:839-849`, Q23); `add_item_to_object_cs` then sets bit 512 on it (`cJSON.c:2095`).

### 6.1 Node store and handles (D11, D12, D14)

- One store owns every node: `Vec` slots and a generational `NodeId` (`Copy + Eq + Hash`). A node holds the C fields:
  `next`, `prev`, `child` as `Option<NodeId>`, the type word as a `u32`-backed flag set, `valueint: i32`,
  `valuedouble: f64`, `valuestring` and the key `string` (owned bytes or a `&'static [u8]`).
- Every C function that takes a `cJSON *` takes a `NodeId` (`Option<NodeId>` where C defines the NULL result). Nodes
  move between the trees of one store. Add, insert, replace and detach do the C pointer surgery exactly
  (`cJSON.c:2027-2058`, `2256-2292`, `2334-2415`), also for a node that is still in another list (D14).
- Cycles are representable: only `array == item` is refused (`cJSON.c:2031`); `duplicate` stops at
  `CJSON_CIRCULAR_LIMIT` (`cJSON.c:2836-2839`) and print at `CJSON_NESTING_LIMIT`. Delete or compare of a live cycle
  stays a divergence (D11).
- References (D12): an `IsReference` node stores the `NodeId` of the shared child, or the caller's `&'static [u8]`
  value; a `StringIsConst` key is a `&'static [u8]`. Delete skips them as C does (`cJSON.c:259-271`).
- A handle whose node was deleted gives `None` / `false` / no effect where C would use freed memory (UB in C).
- Delete and `Drop` do not recurse (D10): a tree built by adds deeper than any stack still deletes.

### 6.2 Allocation hooks (D1, revised 2026-10-10)

```rust
pub trait AllocHooks: Send + Sync {
    /// Called at each C allocation site with C's size; `false` = this allocation fails.
    fn allocate(&self, size: usize) -> bool;
    /// Called at each C free site of a live allocation with the size given to `allocate`.
    fn deallocate(&self, size: usize);
}
pub fn init_hooks(hooks: Option<std::sync::Arc<dyn AllocHooks>>); // process-global, as cJSON.c:186
```

- The seam does not own memory: memory comes from the global allocator, the seam only decides whether a C allocation
  site succeeds and accounts for it. Storage is a `static RwLock<Option<Arc<dyn AllocHooks>>>`. With no hooks
  installed there are no events.
- One event per C call of `hooks->allocate` / `hooks->deallocate`, in the C order, with C sizes: node 64
  (`sizeof(cJSON)` on LP64, `cJSON.c:243`), `strlen + 1` for strings (`cJSON.c:198`), print buffers as A3/Q6 (256
  for `print`, the prebuffer for `print_buffered`, growth `2 * (offset + needed + 1)`). C's `free(NULL)` is no event.
- With custom hooks C has no `reallocate` (`cJSON.c:233-237`): print-buffer growth is `allocate(new)` then
  `deallocate(old)` (`cJSON.c:555-568`), and the final shrink of `print` is `allocate(offset + 1)`, copy,
  `deallocate(old)` (`cJSON.c:1264-1285`). A longer `set_valuestring` value is allocated before the old one is freed.
- `allocate` returning `false` takes the C failure path: the function frees what it built (events included) and
  returns `None` / `false`; every allocation guard of §7 stays.
- Delete emits `deallocate` for node, `valuestring` and key, honouring `IsReference` / `StringIsConst`
  (`cJSON.c:259-271`). Print results and other returned strings (`find_pointer_from_object_to`) are a `Printed`
  type whose `Drop` emits `deallocate`, as the caller's `cJSON_free` in C.
- Remaining difference: a real out-of-memory aborts in Rust where C returns NULL. `cJSON_malloc` / `cJSON_free`
  (`cJSON.c:3197-3205`) are not offered: callers never free library memory by hand (D1).

### 6.3 Parse and the error position (D9, Q12, Q13, Q26)

- The four C entry points keep their argument semantics: input `Option<&[u8]>` (`None` = C NULL), `parse_with_opts`
  reads to the first NUL and counts the terminator inside the buffer (Q13), `parse_with_length*` take the length.
- Result: the root, or a parse error carrying the error offset (Q12); the parse end (`return_parse_end`) is the end
  of the value on success and the error offset on failure.
- `get_error_offset() -> Option<usize>` reads a thread-local `Cell` with the C rules of Q26: `parse(None)` and
  `parse_with_opts(None, ..)` leave it unchanged, every other call resets it and a failure with input sets it.

### 6.4 Strings and writable views (Q10, D7, D13, D21)

- Arguments are `&[u8]` read up to the first NUL; stored values are owned bytes or, for references and const keys,
  the caller's `&'static [u8]`.
- Writable views (D21): `string_value_mut(id) -> Option<&mut [u8]>` stands for the `char *` of
  `cJSON_GetStringValue` and `cJSON_SetValuestring`, and `Printed::bytes_mut()` for the `char *` of the print
  functions. The view is the bytes before the NUL; the caller may overwrite any of them, a NUL included. Every later
  read (get, print, compare, lookup, `set_valuestring`'s length test) sees the write, and a NUL ends the value
  there, as C `strlen` does. The buffer stays where it is.
- Still impossible through a view, all UB or caller-memory cases in C: writing past the current value (into the
  slack of an earlier, longer value or beyond the allocation); overwriting the terminator to lengthen the value;
  using the pointer after a later mutation or delete; writing through a reference's string (`IsReference`, the
  caller's buffer, D13: the view is `None`); writing into a key (`item->string` is a field, not a returned pointer)
  or a const key; two live views, or a view while the tree is read.

### 6.5 Fields, macros and the rest

- `set_valueint` / `set_valuedouble` write one field each with no coupling (C callers write the public fields; Q3:
  a `valuedouble` write without `valueint` gets the `%g` path; user accepted 2026-10-11). Writes to `type` and to
  links are not offered (D14);
  the type changes only through the library and `set_bool_value`.
- The header macros as in §6.0 item 7; `cJSON_ArrayForEach` is a children iterator.
- `cJSON_Utils`: patch functions return `Result<(), PatchError>` with `PatchError::code()` (§7); `ApplyPatches`
  keeps the patches applied before the failing one.
- Feature `locales` is a no-op (D3).

## 7. Error model

- cJSON signals failure by `NULL` / `false` (E2); the parse error position is the global `cJSON_GetErrorPtr()`
  (G3, D9). `cJSON_Utils` patch functions return status codes `0..13` (`cJSON_Utils.c:807-1036`, Q24): Stage 2 keeps
  them as `enum PatchError` with `fn code(self) -> i32` returning the exact C value (E1).
- **allocation-guards**: every `NULL` check after `hooks->allocate`/`reallocate` (e.g. `cJSON.c:199-203`, `243-247`,
  `357-361`, `540-564`, `863-866`, `1166-1170`, `1252-1255`). Both Stages keep them; in Stage 2 the failing
  allocation is an `allocate` hook returning `false` (§6.2, D1).
- **precondition-guards** (kept, same result in both Stages): `NULL` arguments, negative indices and lengths
  (`cJSON.c:1321-1324`, `1352-1355`, `1943-1946`), a node in no list (`cJSON.c:2260`), a first child whose `prev` is
  NULL (`cJSON.c:2050-2055`, reachable through a reference to a node in no list, D14), nesting and circular limits,
  `ensure` size limits (`cJSON.c:500-510`), `noalloc` buffer too small (`cJSON.c:518-520`). Only the corrupted-list

## 10. Judge and acceptance

- Gate: `make pilot-cjson STAGE=<n>` over the feature sets `""` and `locales` (§3), both run in the C locale.
- Upstream tests the Judge links (`tests/CMakeLists.txt`): 18 `cJSON` tests `parse_examples`, `parse_number`,
  `parse_hex4`, `parse_string`, `parse_array`, `parse_object`, `parse_value`, `print_string`, `print_number`,
  `print_array`, `print_object`, `print_value`, `misc_tests`, `parse_with_opts`, `compare_tests`, `cjson_add`,
  `readme_examples`, `minify_tests`, plus 3 `cJSON_Utils` tests `json_patch_tests`, `old_utils_tests`,
  `misc_utils_tests` (data in `tests/inputs/` and `tests/json-patch-tests/`). Unity from `tests/unity`.
- Linking problem: every test includes `tests/common.h`, which does `#include "../cJSON.c"`, so the tests compile the
  C library into themselves. The Judge replaces `common.h` with a shim that includes `cJSON.h`. With that shim, 8
  tests use only the public API (`cjson_add`, `compare_tests`, `json_patch_tests`, `minify_tests`,
  `misc_utils_tests`, `old_utils_tests`, `parse_with_opts`, `parse_examples`) and `readme_examples` needs only a copy
  of `compare_double`. The other 12 use static internals (`parse_*`, `print_*`, `ensure`, `skip_utf8_bom`,
  `global_hooks`, `parse_buffer`, `printbuffer`; `misc_tests` and the `parse_*`/`print_*` files).
  Decision (user, 2026-10-10): Stage 1 exports those internals as `pub` under the cargo feature `test-internals`, with
  `#[repr(C)]` `parse_buffer`/`printbuffer` (c2rust keeps static functions private, so without this the tests
  cannot link). The Differential harness also covers their inputs.
- Stage 1: `cargo check`, `cargo test`, the upstream tests above linked to the staticlib (C only), Differential
  harness (`harness/run.py`: C driver parse → print formatted/unformatted, minify, error position vs original).
- Stage 2: translated tests `rust/tests/upstream.rs`, Differential harness with `rust/examples/dump.rs`, clippy
  `-D warnings`, rustfmt, zero `unsafe`, no `unwrap()`/`expect()` on input-driven paths (others need an invariant
  comment) (decision 10). The harness compares every section of the dump, including the allocator sweep (D1 seam,
  sizes in C bytes, allocations left alive after each failure), the writable views (D21) and field writes (Q3). The
  release build parses and prints a `NESTING_LIMIT`-deep document and duplicates a `CIRCULAR_LIMIT`-deep array on a
  2 MiB thread (D10; `run.py --stage 2` runs it with `cargo test --release`).
- Translated tests that run in Stage 2 through a public-API variant (all of them run in Stage 1 too):
  `ensure_should_fail_on_failed_realloc` (a failed growth allocation of `PrintBuffered`, D1);
  `typecheck_functions_should_check_type` and `cjson_compare_should_compare_invalid_as_not_equal` (the `Invalid`
